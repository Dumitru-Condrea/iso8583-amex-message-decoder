
### 6.3 JWT Caching

The framework caches the final JWT separately for EMV and Gateway authentication.

Token caching is implemented in the shared `AuthService` class, while token expiration is managed by the `AuthToken` model.

Each authentication service maintains its own cached `AuthToken` instance.

The token expiration time is calculated using the `expires_in` value returned by the Authentication API, with an additional 30-second safety margin.

```java
private static final long EXPIRATION_MARGIN_SECONDS = 30;
```

A token is considered valid only while the current time is earlier than its calculated expiration time.

When `getToken()` is called:

1. If a valid cached token exists, it is reused.
2. If the token is missing or has expired, the authentication workflow is executed.
3. The newly obtained JWT replaces the cached token.

This reduces unnecessary authentication requests while avoiding the reuse of tokens that are close to expiration.
