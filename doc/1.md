
# Framework Overview

## 1. Introduction

The EMV & Gateway integration extends the Release Automation Framework (PAFI) with reusable components for automated testing of payment tokenisation services.

The integration supports API-level and end-to-end testing by providing a common approach to service communication, authentication, database access, test data management, and validation of tokenisation workflows.

It is designed to reduce duplicated implementation across Cucumber scenarios and provide consistent, reusable mechanisms for interacting with the underlying services.

The integration consists of several components with clearly defined responsibilities.

| Component | Responsibility |
|---|---|

| EMV Service | Communication with EMV API endpoints |
| Gateway Service | Communication with Gateway and TGS API endpoints |
| Authorization Services | Authentication workflows and JWT management |
| Scenario Context | Tracking API requests, responses, and scenario-related data |

| Token Cleanup | Automated removal of test tokens before and after scenarios |
| TGS Configuration Manager | Tokenisation configuration updates and validation |

## 4. Design Principles

### 4.1 Reusability

Common operations are encapsulated in dedicated services and utilities.

Test scenarios reuse existing clients and operations instead of implementing authentication, HTTP communication, or database access independently.

### 4.2 Separation of Responsibilities

The integration separates API communication, authentication, database access, scenario state management, and configuration validation.

Each component is responsible for a specific part of the testing workflow.

This separation simplifies maintenance and allows individual components to be reused across different test scenarios.

### 4.3 Centralised Service Access

Reusable service clients are exposed through a centralised Singleton-based access layer.

The same access layer also provides access to the Scenario Context, allowing test steps and supporting services to interact with shared framework components consistently.

### 4.4 Configuration-Driven Execution

Service endpoints, database connections, authentication settings, and environment-specific values are managed through configuration properties.

Sensitive credentials used for authentication and MongoDB access are stored in encrypted form.

### 4.5 Automated Test Lifecycle Management

Cucumber hooks and tags are used to manage selected operations automatically.

These include:

- Oracle database connection initialization.
- Token cleanup before and after scenarios.
- WireMock state initialization and restoration.

This reduces the need to explicitly manage these operations in individual test steps.

### 4.6 Consistent Validation

The integration provides reusable mechanisms for validating API responses, database records, and configuration changes.

For example, TGS configuration updates are validated against MongoDB, while token-related test scenarios can verify the corresponding Oracle database records.
